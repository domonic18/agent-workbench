# M1.5 · 沟通契约（轻量版）

> 上位: [../development-plan.md](../development-plan.md) ｜ 出口标准: 缺必填字段的消息被拒收并提示补什么;抽检 20 条可在 10 秒内说清「谁要谁干什么、什么时候要」
> 设计依据: [01](../../arch/01-后端服务设计.md) §5 §8.1 ｜ [02](../../arch/02-数据服务设计.md) §3 §8
> 本文件只列任务与依赖,不维护进度;完成状态只写 `development-plan.md`。

规则本身只是校验与模板,但任务模型与事件去重仍要落库,所以 M1.5 先补最小持久化基线。入库不等于控制台可用——界面在 M3,建单在 M2.5。

| # | 任务 | 产出 | 依赖 | 验收点 |
|---|------|------|------|--------|
| M1.5-1 | 持久化与进程基线 | `src/store/`(better-sqlite3、WAL、`foreign_keys=ON`、forward-only 迁移) + `src/server/main.ts` 启动顺序 | M1-0 | 迁移可重复启动;`workspace/console.lock` 单实例生效;`/healthz` 返回 `db` 状态,库不可写时 503 |
| M1.5-2 | A2A 信封类型与校验 | `src/shared/protocol.ts` + 校验函数与单测 | M1-7 | 未知 `v`、非法 `intent`、超长 `summary` 全部拒收;**缺多项时一次返回全部缺失项** |
| M1.5-3 | 任务模型与迁移 | `src/store/migrations/` 首个迁移 + `src/domain/task/` 状态机 | M1.5-1 | 字段含项目 / 下发人 / 承接 / 阶段 / 状态 / `round` / `rework_count` / `deadline`;非法状态跃迁被拒并有单测 |

**开工前实测(M1.5-4)**: 飞书长连接(WebSocket)是否需要出站白名单或代理;`/api/feishu/callback` 经 `aw.17aitech.com` 收到回调后,签名校验所需的原始 body 是否被 frp 改写、能否取到真实来源 IP。结论写入 M1.5-4 验收记录。

**注意**: 本里程碑**不产生任务**。飞书入站只处理指令并回执,不建单(见 [01](../../arch/01-后端服务设计.md) §8.1);`POST /api/tasks` 与 MCP 工具面在 M2.5-0 落地(五个 Agent 工具,只接受 Agent Bearer;`kb_write` 待知识域就绪后随 M3.5-9 补齐)。控制台永远没有人工建单入口。
