# M3.9 · 确定性协调内核与真实 Bug 闭环

> 设计依据: [01](../../arch/01-后端服务设计.md) §9 ｜ [02](../../arch/02-数据服务设计.md) §3.9 ｜ [03](../../arch/03-前端设计.md) §4.3 ｜ [05](../../arch/05-授权与闸门设计.md) §6.5 ｜ [06](../../arch/06-架构评审记录.md) §16

| # | 任务 | 产出 | 依赖 | 验收点 |
|---|------|------|------|--------|
| M3.9-1 | 确定性 Git Router + WorkItem + worker_inbox | 最小 work_item/work_trigger/work_thread/thread_subscription/worker_inbox 表与事务；Git RouteRule/work_kind 与项目角色解析；Bug/Git/PR/CI Source 适配；work_read/work_inbox/work_ack/work_handback；租约重投与确定性处置审计 | M3.8-3；M3.8-1 定稿的结构化 Bug、Git/CI 契约 | Thread owner 直通、context 不执行；新工作必须命中唯一 RouteRule，无项目/无规则/冲突统一 needs_person，不建 route_evaluation 或在线 Slow；Assignment ACK 绑定承接 Agent 自己的 Task，Input ACK 仅消费；Handback 单事件退回且换绑有审计。重复 webhook 不重复建 WorkItem/inbox；A 不能领取 B；WorkBuddy automation 能真实拉取并处理 Assignment/Input；旧 SHA 绿色 CI 或当前 SHA 红色 CI 不得待验收；原 Bug 接受才 done，退回到同一 WorkItem 形成 input |
| M3.9-2 | 真实 Bug 接受/退回 E2E | 一个真实项目、真实 Bug、真实 worker、真实 PR 与 CI 的验收记录及暴露问题修复；不开发演示专用业务功能 | M3.9-1；真实 Bug 机器人、仓库/CI、目标 worker 就位 | 人只向原 Bug 机器人反馈一次；系统自动完成 WorkItem→Assignment→Agent 自建 Task→实际修复→PR→CI→待验收；先真实退回并在同一 WorkItem 返工，再以真实 PR+CI 待验收，最后原 Bug 机器人接受才 done 并回告；无常规人工催促、无直接 SQL 改态、无自动生产发布，原始 Bug/代码/PR/CI/验收可互相追溯 |

**必须的真实反例**：至少实际制造一次 CI 失败和一次原 Bug 机器人退回；不得以 mock CI、伪造回调或直接改库替代，也不能只验收接受的 happy path。

**明确不做**：在线模型路由、Source Memory 派工、system 伪造 A2A、通用规则编辑器、WorkBuddy 过程采集、新 Bug 收集/查重页面、生产自动发布。
