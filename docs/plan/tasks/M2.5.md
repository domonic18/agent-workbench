**开工前实测(M2.5-4)**: `wait=25s` 长轮询与 Claude Code 的 MCP 工具调用超时上限是否冲突;若客户端先掐断,表现是「那一轮刚到的消息要等下次拉取」,需实测确认不丢件。结论写入 M2.5-4 验收记录。

**后续边界**: 旧「主动唤醒推迟 / WorkBuddy 被动轮询」不再作为目标；WorkBuddy 在 M3.8-3 使用官方 automations，首版 Run/对话/Token 留空。

**上线纪律**: 与 M3 配对上线。没有控制台可见消息去向之前,不切停飞书群通道。
