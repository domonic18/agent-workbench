# M2.5 · A2A 通道（传输层）

> 上位: [../development-plan.md](../development-plan.md) ｜ 出口标准: Agent 间往返脱离飞书群;跨机可达;离线消息不丢且不重复执行
> 设计依据: [01](../../arch/01-后端服务设计.md) §5 §5.1 §6 ｜ [02](../../arch/02-数据服务设计.md) §3.3 §3.7
> 本文件只列任务与依赖,不维护进度;完成状态只写 `development-plan.md`。

| # | 任务 | 产出 | 依赖 | 验收点 |
|---|------|------|------|--------|
| M2.5-0 | MCP 工具面 | `src/mcp/`:五个工具 `task_create` / `task_update` / `a2a_send` / `a2a_inbox` / `a2a_ack`,全部经 MCP proxy 的 `decide()` | M2-5、M2.5-1、M2.5-5 | 只暴露这五个,不向 Agent 开裸 HTTP;`RunContext` 由 proxy 注入,模型传的 `agent_id` / `role` 一律丢弃;`a2a_send` 校验 `task_id` 归属与 `allowed_targets_json`,任一不满足即 deny 并列出当前可达目标;审计写失败即拒绝执行 |
| M2.5-1 | 身份域:机器与 Agent 注册表 | 迁移 `machine` / `agent` + `/api/agents`、`/api/machines` 注册与轮换 | M1-6、M1.5-1 | 明文 `secret` 只在注册响应出现一次;库中只有 `secret_hash`;轮换后旧密钥立即失效;Agent 与采集器两套密钥互不通用 |
| M2.5-2 | A2A 域表与链路列 | 迁移 `a2a_thread` / `a2a_message` / `outbox` / `a2a_dead_letter`;`task` 补 `parent_task_id` | M1.5-3 | 内容与运输分表;`a2a_thread` 对 `(initiator_task_id, responder_agent)` 唯一;`refs` / `auth` 落 JSON 列;`auth_ticket` 只存标识;`parent_task_id` 可空、创建后不可改 |
| M2.5-3 | 发件箱状态机 | `src/reliability/outbox/` | M2.5-2 | 7 态迁移合法;`lease_token` 条件更新,过期租约不能提交结果;`idempotency_key` 重复直接返回首次结果(Agent 发起的 A2A 用客户端 `Idempotency-Key` 原样入库);业务投递 `uncertain` 围栏生效,通知投递不围栏 |
| M2.5-4 | 线程、信箱拉取与 ACK | `/api/a2a/messages`、`/api/a2a/inbox`、`/api/a2a/inbox/:msg_id/ack` | M2.5-1、M2.5-3 | 服务端按 `(发起方任务, 收件方)` 建线程并在事务内分配 `round`,客户端给值被忽略;长轮询 `cursor + wait=25s`;只返回 `to` 为本 Agent 且未 ACK 的消息,跨 Agent 403;未 ACK 在租约过期后重新可见(at-least-once);`delivered` 只以 ACK 为准;ACK `request`/`escalate` 缺自己 `task_id` 返回 422,并同事务写下游 `parent_task_id` 与 `handoff` 事件,`reply`/`notify` 的 ACK 不收 `task_id` |
| M2.5-5 | Agent 侧 Bearer 鉴权 | 中间件:解析 `Authorization: Bearer <agent_id>.<secret>` + 常量时间比对 | M2.5-1 | 采集器密钥与 Agent 密钥不可互换使用;不存在与不匹配返回同一 401;重放由 `Idempotency-Key` / `msg_id` 幂等吸收,不靠签名 |
| M2.5-6 | 死信巡检与回执 | 作业 + `a2a_dead_letter` 写入 | M2.5-3 | `deadline` 过期未 ACK → `failed` + 死信 + 回执「已过期,请重新发起」;`notify` 免 `deadline`;不自动重发 |
| M2.5-7 | 跨机双机验收 | 两机往返实测记录 | M2.5-4、M2.5-6 | Agent 间往返不经飞书群;停机期间消息排队,恢复后补投;同一 `msg_id` 不重复执行;链式样本 `A→B→C` 的每一环可沿 `parent_task_id` 上溯,链头无任务时止步不补建 |

**不做**: 主动唤醒(`notify` 之外的 turn 注入)推迟;WorkBuddy 侧按 5 分钟上限被动轮询,长轮询优先、定时兜底。理由见需求 §8-B3。

**上线纪律**: 与 M3 配对上线。没有控制台可见消息去向之前,不切停飞书群通道。
