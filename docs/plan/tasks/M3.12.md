# M3.12: 派发链路自愈与可观测

> 依赖：M3.10（派发闸门 G1–G4 与批次交付——本里程碑在闸门链上加自愈与可见性，不动闸门判定本身）。

## 背景

2026-11-11 两起事故同根：**「下发→ACK→冻结」配置管道同时承载了两种所有权不同的状态**。

- 仓库 aitech-hub 挪位后，固化的 cwd 让调度器每 30s 对 cc-sysdev 打「Agent 工作目录不存在，跳过调度」WARN（仅 aw-node.err 本地日志，控制台不可见），A2A 消息两轮死信。cwd 的事实源是机器上的 cc-connect 配置，本不该由控制台下发冻结。
- 早上的密钥失配是同一模式的另一半：ACK 过的 Agent 永不重发、不能自愈，只能人肉 `UPDATE agent SET config_ack_at = NULL`。密钥的事实源在控制台，下发+ACK 是对的，缺的是失效检测与重发。

## 设计原则（三原则）

1. **密钥归控制台**：补自愈——探视连续 3 轮 401 判 `auth_stale` 自动清回执（10min 冷却防轮换风暴）；rotate 与自助兑换联动清 `config_ack_at`。
2. **cwd/MCP 绑定归机器自维护**：调度每轮实时解析（直接扫 cc-connect 配置），受管 MCP 条目由 config-sync 用本机现存密钥自迁移到新 cwd。
3. **任何「有活派不出去」必须上报可见**：挂起原因/件数/起点随心跳上报，总览徽标 + 协作群首跳播报，不再只写本地 WARN。

## 任务

### M3.12-1: 派发链路自愈与可观测改造

- **范围**：collector（cwd 实时解析、`cwd_unknown`/`cwd_missing` 挂起、MCP 条目自迁移、派发状态采集、`auth_stale` 检测、心跳捎带 `dispatch`）；console（迁移 `0019` `machine.dispatch_status`、心跳接收、auth_stale 自愈、rotate 联动清 ack、首跳播报、总览透出）；web（挂起徽标 + Tooltip、overview 60s 轮询）。
- **完成判据（真机）**：
  1. 仓库挪位 + config.toml 改好后，升级 aw-node ≤5min 自动跟随新 cwd 并 spawn，无需人工 SQL；
  2. 临时改目录名 → 总览出「派发挂起·目录不存在」徽标 + 协作群首跳卡片；改回后自愈、徽标消失；
  3. rotate 后新密钥自动重达机器（`config_ack_at` 重新置位）；
  4. 重发 A2A 给 cc-sysdev，回执闭环。
