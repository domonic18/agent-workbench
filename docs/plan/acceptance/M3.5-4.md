# M3.5-4 索引链 验收记录

> 归属: M3.5-4 索引链 ｜ 验收日期: 2026-11-01 ｜ 依赖: M3.5-2(知识状态机与来源字段)
> 出口标准: 重建走 worker_thread,不阻塞事件循环;`content_hash` 未变不重嵌入;`pending` / `failed` 在列表打标并可单条重试。

## 结论

开工前三项实测全部成立,方案按实测结论定稿:

1. **中文 FTS5**:SQLite 3.53.4 的 `unicode61` 把整段中文当作一个 token,子串查询全部落空;`trigram` 可召回 ≥3 字的子串,但 2 字词(如「交接」)返回 0。索引层取 `trigram`,1~2 字查询的兜底放到检索层 M3.5-6 用 `LIKE` 补,不自造分词器。
2. **sqlite-vec**:0.1.9 在 macOS 可加载;worker_thread 能独立打开同一 WAL 库并加载扩展,与主线程句柄不冲突。better-sqlite3 13 把 JS number 绑成 REAL,`vec0` 主键必须 `CAST(? AS INTEGER)` 或传 BigInt,否则报 "Only integers are allows for primary key values"。
3. **备份**:`sqlite3 .backup` 无法按表跳过 `vec0` 影子表;整库一致性备份本身安全,恢复后查询向量表前必须先加载扩展。默认以整库备份 + 重建兜底,不改 `scripts/backup.sh`。

索引链落地:

- 迁移 `0018_knowledge_index`:`knowledge_entry` 增 `content_hash` / `embedding_status`;`knowledge_chunk` 以 `(entry_id, chunk_no)` 唯一并随条目级联删除;`knowledge_fts` 用 `trigram`,触发器随分块增删改同步。
- `knowledge_vec` 不在迁移里建,首次需要向量时懒建;未配置嵌入或扩展加载失败即降级为纯关键词,条目保持 `pending`,控制台启动不依赖原生扩展。
- 索引器先算哈希、分块与批量嵌入(异步),再在**单事务**内替换分块 / FTS / 向量并更新 `content_hash` 与状态,重建中途不会被检索读到半成品;`content_hash` 未变且 `ready` 直接跳过;嵌入失败仍写关键词索引并标 `failed`。
- 整库重建在 worker_thread 执行,主进程事件循环与 HTTP 请求不被嵌入调用阻塞;开发态(`tsx`)与构建产物(`dist`)两种入口均实测可跑。
- 接口:`POST /api/knowledge/rebuild`(202 接受,409 防并发)与 `POST /api/knowledge/entries/:id/reindex`(单条重试;条目不存在 404、文件缺失 409、整库重建期间 409)。

`make check` 全绿:服务端 546 用例、前端 66 用例。

## 口径

| 项 | 取值 | 说明 |
|----|------|------|
| 分块上限 | 800 码点 | 按空行切段后合并;超长段按码点硬切,不劈开代理对 |
| 嵌入批次 | 16 条/次 | `KNOWLEDGE_INDEX.embedBatchSize` |
| 向量维度 | 768 | 与 `vec0 float[768]` 固定一致;不一致按失败处理,不截断 |
| 嵌入接口 | OpenAI 兼容 `/embeddings` | `EMBEDDING_BASE_URL` + `EMBEDDING_MODEL` 必须成对;`EMBEDDING_API_KEY` 可选 |
| 跳过条件 | 哈希未变且 `embedding_status = ready` | `pending` / `failed` 即使哈希未变也会重跑,供重试 |
| 降级 | 未配嵌入 → `pending` + 仅关键词 | 无需任何补丁即可检索关键词 |

`pending` / `failed` 的**列表打标**由 M3.5-3 知识屏渲染;本里程碑保证字段与单条重试接口存在。

## 已知边界

- **2 字查询召回**由 M3.5-6 的 `LIKE` 兜底承担,本层只保证 trigram 索引存在。
- **向量残留**:`knowledge_vec` 与 `knowledge_chunk` 无外键,物理删除条目会留下孤儿向量。当前策略是 `deleted_at` 软删除、不物理删正文(M3.5-5),检索按分块 join 过滤;整库重建可清残留。
- **tsx worker**:worker_thread 不继承主线程的 `.js → .ts` 解析钩子,开发态入口在 worker 内显式注册 `tsx/esm/api` 的 `register()`;构建产物跳过该分支,生产镜像无需 tsx。
- **单条重试不做结果去重**:重建天然幂等(同内容同结果),沿用控制台写路由的 CSRF + 幂等键门卫。
