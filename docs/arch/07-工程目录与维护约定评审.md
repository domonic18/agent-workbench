## 2. P0 · 阻断正确性

### [x] P0-1 目录模型未定,且与 00 §3 冲突

- **现状**:00 §3 的目录树是 `src/server`、`web/`、`collector/`,实际骨架是单包 `src/`,既无 `web/`、`collector/`,也无共享协议包落点。
- **后果**:web 端要用服务端类型时只能 `import ../src/...`,越层依赖从第一天就成立;`collector/` 无归属,04 的采集器无处安放。
- **建议**:二选一并回填 00 §3 与根 `CLAUDE.md` §2:
  - **甲**:pnpm workspace,`apps/server` / `apps/web` / `apps/collector` / `packages/shared` —— 贴近 agent-sims,全 TS 项目最顺;
  - **乙(已定 2026-10-29)**:保持 00 原样 `src/server` / `web` / `collector` / `src/shared`,用 workspace 只包 `src/*`。根 `CLAUDE.md` §2 已按此回填 `web/`、`collector/` 与 shared 边界。
- **落地**:乙方案目录已按 00 §5 建出;`web/` 与 `collector/` 进入 pnpm workspace,暂为无依赖的空包,避免提前锁定 React / Vite 版本。

### [x] P0-2 脚手架空壳会被误判为可运行

- **现状**:`make install` → `npm install`(无 package.json),`make dev/check/test` → 不存在的 script。README 标注了「就绪后」,Makefile 无任何提示。
- **建议**:二选一 —— M1 一次性补 `package.json` + `tsconfig` + `eslint` + `vitest`,让 `make check` 真跑通;或现在把目标改为 `@echo "尚未就绪:见 docs/plan M1"`。不允许长期保留「看起来能跑」的入口。
- **落地(2026-10-29)**:补 `package.json` / `pnpm-workspace.yaml` / `tsconfig.base.json` / `tsconfig.build.json` / `eslint.config.js` / `vitest.config.ts`,并加最小 `/healthz` 入口与单测。`make check`(typecheck + lint + test)实测通过,`make build` 产出 `dist/`,构建产物可直接 `node dist/server/main.js` 启动。

### [x] P0-3 无 `docker/` 与 `.dockerignore`,交付姿势无落点

- **现状**:00 部署全景依赖 frpc 容器(`localIP host.docker.internal`)与 Teleport CE,但仓库无 Dockerfile / compose / `.dockerignore`。
- **建议**:
  - `docker/Dockerfile.console`:多阶段构建、非 root 用户、暴露 `/healthz`;
  - `docker/docker-compose.yml`:console + frpc,`../workspace:/app/workspace` bind mount;
  - 根 `.dockerignore`:排除 `node_modules`、`workspace`、`docs`,否则 SQLite 库与 spool 会灌进构建上下文。
- **落地(2026-10-29)**:三件套已就位。额外补 `docker/frpc.toml.example`(含两条独立规则、密钥走 env 模板)与 compose 的 `tunnel` profile,并注明容器内 `localIP` 用服务名、控制台跑宿主机时改 `host.docker.internal`。

### [x] P0-4 `.env.example` 缺采集器 / 授权 / 飞书回调的关键变量

- **现状**:样例只有 `NODE_ENV / HOST / PORT / LOG_LEVEL / DATABASE_PATH / CONSOLE_PASSWORD / FEISHU_APP_ID / FEISHU_APP_SECRET`。
- **缺口**:04 §8 需要 `AW_INGEST_URL` / `AW_COLLECTOR_ID` / `AW_COLLECTOR_SECRET`;01 §8 飞书回调需要校验 token / encrypt key;01 §3 会话 cookie 需要签名密钥;05 需要 Teleport 地址与角色。
- **附带坑**:`HOST=127.0.0.1` 在容器内会直接导致端口不可达(容器内必须 `0.0.0.0`,对外由 compose 只绑 `127.0.0.1`)。
- **建议**:照 ai-invest 的分节写法 `[共用] / [Compose] / [服务器] / [采集器] / [不在 env 而入库]`,并在每项标注代码落点(如 `src/config/env.ts`)。坑注释直接写在变量旁。
- **落地(2026-10-29)**:已按「共用 / 服务器 / 飞书 / 采集器 / Agent 检索 / Teleport / compose / frpc」分节,补齐 `SESSION_SECRET`、`FEISHU_VERIFICATION_TOKEN`、`FEISHU_ENCRYPT_KEY`、`FEISHU_ALLOWED_OPEN_IDS`、`AW_INGEST_URL`、`AW_COLLECTOR_ID/SECRET`、`AW_KB_SEARCH_SECRET`、`TELEPORT_*`、`AW_UID/AW_GID`、`FRP_*`。容器 `HOST=0.0.0.0` 的坑写在变量上方。
