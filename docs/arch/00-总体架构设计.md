## 1. 项目定位

把散落在飞书群、黑板表格、本地脚本里的多 Agent 协作，收进一个**可看、可控、可计量**的工作台。

- **产品形态**：控制台 + 飞书双面并存。控制台管「状态与权力」，飞书管「说话与拍板」；控制台不做 IM。
- **核心用户**：持有多个 Agent（WorkBuddy / cc-connect + Claude Code）的个人开发者，当前唯一用户。
- **一期四屏**：总览 / 任务 / 授权 / 知识。
- **不替换运行时**：Claude Code 与 cc-connect 是资产，本项目只补控制面。

## 2. 部署架构全景图

```
┌──────────────────────────────────────────────────────────┐
│ 手机浏览器 / 电脑浏览器 / 飞书网页应用（二期 iframe）      │
└──────────────────────────────────────────────────────────┘
                          │ HTTPS
                          ▼
┌──────────────────────────────────────────────────────────┐
│ frps — aw / tp.17aitech.com；vhost 80/443，tcp 8443       │
└──────────────────────────────────────────────────────────┘
                          │ 加密隧道（token + TLS）
                          ▼
┌──────────────────────────────────────────────────────────┐
│ frpc — MacBook，Docker 容器（两条规则，互不复用）          │
│  ① http     aw.17aitech.com → host.docker.internal:8787   │
│  ② tcp  tp.17aitech.com:8443 → host.docker.internal:443   │
└──────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────┐
│ 控制面进程 — 127.0.0.1:8787（Node / TypeScript）          │
│   HTTP + SSE │ 口令登录 │ /healthz │ /api/ingest          │
│   领域服务：任务 / 总览 / 授权 / 知识 / 通知               │
│   可靠性：事件日志 · 发件箱 · 预算账本                     │
│   存储：SQLite（workspace/console.db）+ Markdown 知识库    │
└──────────────────────────────────────────────────────────┘
        ▲                      │                      │
        │ POST /api/ingest     │ 飞书 OpenAPI          │ 短时证书
        │                      ▼                      ▼
  采集器（每台机一个）      飞书开放平台          Teleport CE (MacBook)
  MacBook / macmini         入站消息 / 卡片        auth + proxy
  launchd 常驻              回调签名校验           tp.17aitech.com
  会话文件增量读取                                 tbot: 15 分钟证书
                                                   node agent: 目标机
```

**边界约定**：

1. 控制台只绑 `127.0.0.1:8787`，不处理 TLS；公网暴露全部由 frp 承担。
2. frpc 需**两条独立规则**：`aw.17aitech.com → 8787`（http）与 `tp.17aitech.com:8443 → 443`（tcp，给 Teleport proxy）。本项目只交付配置片段，不运维 frps。
   - Teleport 为什么不用 443：frps 的 443 已被 `*.17aitech.com` 通配证书的 HTTPS vhost 占用（`dev.17aitech.com` 等站点在此），而 Teleport proxy 自带 TLS、需要 **TCP 透传**，不能与 TLS 终止的 vhost 共享端口。故用独立 tcp `remotePort = 8443`（2026-10-30 裁决）。
3. Teleport CE 独立于控制面进程，控制台只消费其签发的凭证与审计事件；Teleport CE 为 **AGPL-3.0**，以独立进程/容器运行，不与本项目代码链接。
4. 每台运行 Agent 的机器各部署一个采集器（MacBook、macmini 各一），只能通过 `/api/ingest` 单向推事件。
5. 控制面进程必须单实例：启动时获取 `workspace/console.lock`，已有活进程持锁则拒绝启动。
6. frpc 规则 ① 的 `localIP` 随部署形态变：控制台以 compose 运行时指向服务名 `console:8787`；控制台跑宿主机进程时改回 `host.docker.internal:8787`。规则 ② 始终指向 Teleport proxy 的 443，仅公网侧端口为 8443。
7. **控制台机器人只有一个**，与各 Agent 自己的飞书机器人互不相干。Agent 的机器人是它们各自的身份（7 个 Agent 就是 7 个），控制台既不订阅也不读取它们的消息——需求 §1.2 明确机器人之间互相不可见。控制台只持有一个自建应用的凭据，用于发审批卡片与收回执；多接一个 bot 就多一套 `APP_ID` / 验签密钥，且会把 Agent 的私聊搬进控制台。

│ 接入层                                                             │

└────────────────────────────────────────────────────────────────────┘

│ 领域与可靠性层（不依赖 HTTP，可单测）                               │
│ 事件日志 · 时间线与版本号 · 发件箱状态机 · 预算账本 · 能力判定      │

└────────────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌────────────────────────────────────────────────────────────────────┐
│ 数据层                                                             │
│ SQLite（业务表 + 事件日志 + FTS5 全文 + 向量索引）                  │

└────────────────────────────────────────────────────────────────────┘

**分层纪律**：

- 依赖方向只能向下。路由层禁止直接访问数据库。
- 领域层不引入 HTTP / 飞书 SDK 类型，保证可脱离进程单测。
- 外部系统（飞书 / Teleport / 采集器）一律通过适配器接入，接口在领域层定义。

## 4. 技术选型总览

| 层次 | 技术 | 状态 | 理由 |
|------|------|------|------|
| 运行时 | Node.js 22（Jod 维护线，与全机其他项目一致）+ TypeScript 6.0.3 | **已定** | 单机优先；与采集器同语言；类型安全。26 虽是 Active LTS，但本机其他项目仍在 22，**统一版本优先于追新**；整机升级时一起走 |
| 进程模型 | 单进程控制面 | **已定** | 单用户单机，无横向扩展需求 |
| Web 框架 | Fastify 5.12.7 | **已定**（已装） | schema 校验、钩子、SSE 成熟；比 Express 快且类型友好 |
| 参数校验 | zod 4.6.7（路由层可叠加 Fastify JSON Schema） | **已定**（已装） | 边界校验一致；fail-closed |
| 存储 | SQLite + better-sqlite3 13.0.3 | **已定**（已装） | 同步 API 简单可靠；WAL 支持并发读。**重活（索引重建 / `.backup` / 批量清理）必须走 worker_thread 或子进程**，不得阻塞事件循环 |
| 检索 | FTS5 + sqlite-vec 0.1.9 | **已定**（sqlite-vec 于 M3.5 装入） | 与 SQLite 同库，零外部依赖 |
| 前端 | React 19.3.1 + Vite 8.3.5 | **已定**（M3 装入） | 生态成熟；与既有项目经验一致 |
| 实时推送 | SSE（Fastify 原生流式响应） | **已定** | 单向推送足够；比 WebSocket 简单、可经 frp 透传 |
| 样式 | CSS Modules | **已定** | 四屏规模，避免重设计系统；不引 Tailwind，省一层构建与样式约定 |
| 日志 | pino（Fastify 内置） | **已定** | 结构化 JSON；只记事件不记敏感值 |
| 授权 | Teleport CE + tbot | **已定** | 不自研证书签发与续期 |
| 公网穿透 | frp | **已定** | 复用既有基础设施 |
| 跨机采集 | Node 采集器 + launchd | **已定** | 贴近数据源，负责增量读取与心跳 |
| 测试 | Vitest 5.0.5（peer 需 vite 8.3.5，已装根） | **已定**（已装） | 与 Vite 同体系；v5 起 vite 为必选 peer |
| 工具链 | TypeScript 6.0.3 / ESLint 10.13.0 / tsx 4.23.15 | **已定**（已装） | 精确锁版，见根 `package.json` |
| 质量闸门 | `make check`（类型 + lint + 测试） | **已定** | 见根 CLAUDE.md §4 |

> **选型裁决（2026-10-30，M1-4；同日复核运行时版本）**：本表已无「建议 / 待定」项，全部转「已定」。
> 标注「已装」的依赖已写在根 `package.json` 并精确锁版（`.npmrc` 设 `save-exact=true`，不再出现 `^` 漂移）；
> 标注里程碑的依赖（React / sqlite-vec）确定版本但不提前安装，到对应里程碑落地时按锁定版本装入，避免装一堆当下不用的包。
> 不选 Tailwind 的理由是四屏无设计系统需求；不选 TS 7（原生编译器）的理由是 typescript-eslint 8.72.1 的 peer 仍写 `>=4.8.4 <6.1.0`，升上去 lint 直接不可用，故钉在 6.0.3。
> 运行时版本已按 `nodejs.org/dist` 复核：26 为 Active LTS（2026-10-28 转正），22 进维护期（2027-04 EOL）。**裁决取 22**——本机 ai-invest / agent-sims / lokta-acore-manager 均跑在 22，跨项目统一运行时比单项目追新更重要；升 26 时整机一起走，届时只需改 `.nvmrc` / `engines` / 镜像基础镜像三处。
> 容器内用显式 `npm i -g pnpm@9.15.9` 而非 `corepack enable`：corepack 在 Node 25+ 已移除，显式安装跨版本可用。

## 6. 核心数据流

三条主链路：采集（只推）、飞书（出入口，不建单）、Agent（MCP 工具）。

```
会话文件（Claude Code / cc-connect）
        │ 增量读取（inode + offset）
        ▼
本机采集器 ──POST /api/ingest──▶ 归一化 + 幂等去重
        │                              │
        │ 失败进本地 spool             ▼
        │                        事件日志（append-only）
        │                              │
        │                              ├──▶ 读模型投影（总览 / 任务）
        │                              ├──▶ SSE 实时帧（带 revision）
        │                              └──▶ 预算账本（成本事件）
        ▼
    重试 / ACK
```

```
飞书（控制台机器人）
  ├─ 入：卡片回调 / 指令消息 ──▶ 验签 + open_id 白名单 + event_id 去重
  │                              ├─ 审批动作 ──▶ capability（**不建单**）
  │                              └─ 指令 ──▶ 解析后回执；未命中回「不支持」，不转发
  └─ 出：发件箱（状态机）──▶ 卡片 / 通知 ──▶ 回执 / 未知 / 失败
                                                  │
                                                  └──▶ 对账与人工裁决
```

```
Agent（Claude Code / WorkBuddy）
   │ MCP 工具：task_create / task_update / a2a_send / a2a_inbox / a2a_ack
   ▼
MCP proxy ──decide()──▶ 控制台（Bearer Agent 密钥）
   │                        │
   │                        ├──▶ task / task_event（谁干活谁建单）
   │                        ├──▶ a2a_message + outbox（对端拉取）
   │                        └──▶ capability（授权必须挂 task_id）
   ▼
结果同步返回 Agent
```

**可见性边界**：控制台看不到人与其他机器人的私聊，机器人在飞书里也互相不可见（见需求 §1.2）。所以「Agent 干了什么」只有两个来源：采集器推的 run（过程）与 Agent 自报的 task（账目）。跨 Agent 协作一律经 A2A，不依赖群内转述。

## 8. 架构铁律

1. **单一事实源**：没进控制台库 = 没发生；不使用黑板，不做投影。
2. **控制面不承担 IM**：飞书只做输入输出口。
3. **可靠性靠状态机 + 持久化 + 幂等键**，不靠重试与轮询兜底。
4. **外部输入边界校验，失败即拒**（fail-closed），不做静默降级。
5. **系统密钥仅存 env，主体密钥只存哈希**：会话签名、登录口令、飞书凭据、采集器/Agent 的共享密钥原文只在 env；Agent / 采集器密钥由控制台签发，库中只存 `secret_hash`，明文仅签发时返回一次。日志记事件不记敏感值。
6. **凭证短时化**：15 分钟 TTL，自动续期，吊销以自然过期为主。
7. **迁移 forward-only**：禁止手改已应用迁移。
