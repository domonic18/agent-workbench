## 1. 项目定位

把散落在飞书群、黑板表格、本地脚本里的多 Agent 协作，收进一个**可看、可控、可计量**的工作台。

- **产品形态**：控制台 + 飞书双面并存。控制台管「状态与权力」，飞书管「说话与拍板」；控制台不做 IM。
- **核心用户**：持有多个 Agent（WorkBuddy / cc-connect + Claude Code）的个人开发者，当前唯一用户。
- **一期四屏**：总览 / 任务 / 授权 / 知识。
- **不替换运行时**：Claude Code 与 cc-connect 是资产，本项目只补控制面。

## 2. 部署架构全景图

```
┌──────────────────────────────────────────────────────────┐
│ 手机浏览器 / 电脑浏览器 / 飞书网页应用（二期 iframe）      │
└──────────────────────────────────────────────────────────┘
                          │ HTTPS
                          ▼
┌──────────────────────────────────────────────────────────┐
│ frps — 公网 443，aw / tp.17aitech.com                     │
└──────────────────────────────────────────────────────────┘
                          │ 加密隧道（token + TLS）
                          ▼
┌──────────────────────────────────────────────────────────┐
│ frpc — MacBook，Docker 容器（两条规则，互不复用）          │
│  ① http     aw.17aitech.com → host.docker.internal:8787   │
│  ② https/tcp tp.17aitech.com → host.docker.internal:443   │
└──────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────┐
│ 控制面进程 — 127.0.0.1:8787（Node / TypeScript）          │
│   HTTP + SSE │ 口令登录 │ /healthz │ /api/ingest          │
│   领域服务：任务 / 总览 / 授权 / 知识 / 通知               │
│   可靠性：事件日志 · 发件箱 · 预算账本                     │
│   存储：SQLite（workspace/console.db）+ Markdown 知识库    │
└──────────────────────────────────────────────────────────┘
        ▲                      │                      │
        │ POST /api/ingest     │ 飞书 OpenAPI          │ 短时证书
        │                      ▼                      ▼
  采集器（每台机一个）      飞书开放平台          Teleport CE (MacBook)
  MacBook / macmini         入站消息 / 卡片        auth + proxy
  launchd 常驻              回调签名校验           tp.17aitech.com
  会话文件增量读取                                 tbot: 15 分钟证书
                                                   node agent: 目标机
```

**边界约定**：

1. 控制台只绑 `127.0.0.1:8787`，不处理 TLS；公网暴露全部由 frp 承担。
2. frpc 需**两条独立规则**：`aw.17aitech.com → 8787`（http）与 `tp.17aitech.com → 443`（https/tcp，给 Teleport proxy）。本项目只交付配置片段，不运维 frps。
3. Teleport CE 独立于控制面进程，控制台只消费其签发的凭证与审计事件；Teleport CE 为 **AGPL-3.0**，以独立进程/容器运行，不与本项目代码链接。
4. 每台运行 Agent 的机器各部署一个采集器（MacBook、macmini 各一），只能通过 `/api/ingest` 单向推事件。
5. 控制面进程必须单实例：启动时获取 `workspace/console.lock`，已有活进程持锁则拒绝启动。
6. frpc 规则 ① 的 `localIP` 随部署形态变：控制台以 compose 运行时指向服务名 `console:8787`；控制台跑宿主机进程时改回 `host.docker.internal:8787`。规则 ② 始终指向 Teleport proxy。

```
└────────────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌────────────────────────────────────────────────────────────────────┐
│ 数据层                                                             │
│ SQLite（业务表 + 事件日志 + FTS5 全文 + 向量索引）                  │

└────────────────────────────────────────────────────────────────────┘
```

**分层纪律**：

- 依赖方向只能向下。路由层禁止直接访问数据库。
- 领域层不引入 HTTP / 飞书 SDK 类型，保证可脱离进程单测。
- 外部系统（飞书 / Teleport / 采集器）一律通过适配器接入，接口在领域层定义。

## 4. 技术选型总览

| 层次 | 技术 | 状态 | 理由 |
|------|------|------|------|
| 运行时 | Node.js ≥ 22 + TypeScript | **已定** | 单机优先；与采集器同语言；类型安全 |
| 进程模型 | 单进程控制面 | **已定** | 单用户单机，无横向扩展需求 |
| Web 框架 | Fastify | 建议 · M1 定稿 | schema 校验、钩子、SSE 成熟；比 Express 快且类型友好 |
| 参数校验 | zod（或 Fastify JSON Schema） | 建议 · M1 定稿 | 边界校验一致；fail-closed |
| 存储 | SQLite + better-sqlite3 | 已定 SQLite，驱动建议 | 同步 API 简单可靠；WAL 支持并发读。**重活（索引重建 / `.backup` / 批量清理）必须走 worker_thread 或子进程**，不得阻塞事件循环 |
| 检索 | FTS5 + sqlite-vec | 建议 · M1 定稿 | 与 SQLite 同库，零外部依赖 |
| 前端 | React 18 + Vite + TypeScript | 建议 · M1 定稿 | 生态成熟；与既有项目经验一致 |
| 实时推送 | SSE | 建议 · M1 定稿 | 单向推送足够；比 WebSocket 简单、可经 frp 透传 |
| 样式 | CSS Modules（或 Tailwind） | 待定 | 四屏规模，避免重设计系统 |
| 授权 | Teleport CE + tbot | **已定** | 不自研证书签发与续期 |
| 公网穿透 | frp | **已定** | 复用既有基础设施 |
| 跨机采集 | Node 采集器 + launchd | **已定** | 贴近数据源，负责增量读取与心跳 |
| 测试 | Vitest | 建议 · M1 定稿 | 与 Vite 同体系 |
| 质量闸门 | `make check`（类型 + lint + 测试） | **已定** | 见根 CLAUDE.md §4 |

> 标注「建议」的项尚未裁决，需在 M1 选型时确认并回填本文与 `plan/development-plan.md`。

## 5. 项目目录结构（目标形态）

```
agent-workbench/
├── src/
│   ├── server/                 # 进程入口、路由、中间件、静态托管
│   │   ├── routes/             # overview / tasks / capabilities / knowledge / ingest / stream / auth
│   │   ├── middleware/         # 登录校验、错误处理、请求追踪
│   │   └── main.ts             # 绑定 127.0.0.1:8787
│   ├── domain/                 # 领域模型与规则（无 HTTP 依赖）

│   │   ├── capability/         # 能力判定与审批
│   │   ├── knowledge/          # 条目、索引、重建
│   │   ├── run/                # 运行事件与时间线
│   │   └── budget/             # 计费与预算
│   ├── reliability/            # 事件日志、发件箱、幂等、对账
│   ├── store/                  # SQLite 访问、迁移、仓储
│   │   ├── migrations/         # forward-only 迁移，单一真相源
│   │   └── repositories/       # 只构造查询，不管理事务
│   ├── adapters/               # 飞书 / Teleport / 采集器协议适配
│   └── shared/                 # 类型、常量、错误码、时间与金额工具
├── web/                        # React SPA 源码
│   ├── src/pages/              # Overview / Tasks / Capabilities / Knowledge
│   ├── src/components/         # 布局、表格、抽屉、状态徽标
│   ├── src/api/                # REST 客户端与 SSE 订阅
│   ├── src/stores/             # 服务端状态与本地 UI 状态
│   └── src/shared/             # 纯前端展示映射与格式化
├── collector/                  # 跨机采集器（独立构建产物）
├── scripts/                    # 运维与工具脚本（备份等）
├── e2e/                        # 端到端与冒烟；单测就近放在被测文件旁
├── docker/                     # Dockerfile.console · docker-compose.yml · frpc.toml.example
└── workspace/                  # 宿主机持久化数据（gitignore 不入库）
    ├── backups/                # SQLite 一致性备份
    └── collector/              # 采集器 spool
```

根目录工程文件：`package.json`（pnpm 入口）、`pnpm-workspace.yaml`、`tsconfig.base.json`、`eslint.config.js`、`vitest.config.ts`、`Makefile`、`.dockerignore`。

目录设计原则见根 CLAUDE.md §2；新增顶层目录需先在本文档登记。

**`src/shared` 与 `web/src/shared` 的边界**：前者只放**可被服务端与采集器共享**的协议类型、错误码、常量（构建期由 `web` 以路径别名引用，不复制）；后者只放**纯前端**的展示映射与格式化。禁止两侧各自维护同一份业务枚举。

## 6. 核心数据流

```
会话文件（Claude Code / cc-connect）
        │ 增量读取（inode + offset）
        ▼
本机采集器 ──POST /api/ingest──▶ 归一化 + 幂等去重
        │                              │
        │ 失败进本地 spool             ▼
        │                        事件日志（append-only）
        │                              │
        │                              ├──▶ 读模型投影（总览 / 任务）
        │                              ├──▶ SSE 实时帧（带 revision）
        │                              └──▶ 预算账本（成本事件）
        ▼
    重试 / ACK
```

```
飞书消息 ──▶ 通信契约校验（缺必填即拒收）
                     │ 通过
                     ▼
              任务 / A2A 消息（控制台库为真相源）
                     │
                     ▼
              发件箱（状态机）──▶ 投递 ──▶ 回执 / 未知 / 失败
                                            │
                                            └──▶ 对账与人工裁决
```

## 8. 架构铁律

1. **单一事实源**：没进控制台库 = 没发生；不使用黑板，不做投影。
2. **控制面不承担 IM**：飞书只做输入输出口。
3. **可靠性靠状态机 + 持久化 + 幂等键**，不靠重试与轮询兜底。
4. **外部输入边界校验，失败即拒**（fail-closed），不做静默降级。
5. **系统密钥仅存 env，主体密钥只存哈希**：会话签名、登录口令、飞书凭据、采集器/Agent 的共享密钥原文只在 env；Agent / 采集器密钥由控制台签发，库中只存 `secret_hash`，明文仅签发时返回一次。日志记事件不记敏感值。
6. **凭证短时化**：15 分钟 TTL，自动续期，吊销以自然过期为主。
7. **迁移 forward-only**：禁止手改已应用迁移。
