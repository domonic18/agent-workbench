# agent-workbench 总体架构设计

> 创建日期: 2026-10-29
> 本文是终态方案入口;细化设计按主题另开编号文档(01、02…),并在 docs/README.md 登记索引。

## 1. 技术选型

- 运行时：Node.js + TypeScript
- 存储：SQLite（嵌入式，单机优先）
- 控制台：本地 Web 服务，绑定 `127.0.0.1:8787`
- 对外访问：frp 反向代理穿透（不作为本项目工作项）；跨机通信复用同一条 frp 入口
- 访问授权：Teleport CE + tbot（SSH / 数据库短时证书，15 分钟 TTL，自动续期）
- 跨机采集：每台机一个采集器（Node，launchd 常驻），推事件到 `/api/ingest`
- 前端形态、Web 框架与 SQLite 驱动：**待 M1 选型定稿**

**选型理由**: 单机优先、零外部依赖、数据可在宿主机直接备份与重置；控制台只做控制面，不需要分布式存储。

## 2. 系统拓扑

```
手机 / 电脑 / 飞书网页应用（iframe）
        │ HTTPS
        ▼
 frps（公网 443，aw.17aitech.com）
        │ 加密隧道（token + TLS）
        ▼
 frpc（MacBook，转发 127.0.0.1:8787）
        ▼
 控制台进程（Node / TypeScript，SQLite）
        ├── 控制台库：task / a2a_message / capability / agent_run
        ├── 工具调用闸门（分类 / 拦截 / 审批 / 审计）
        ├── 知识层（kb + 向量检索 + MCP）
        ├── 采集接入：/api/ingest（各机采集器推送）
        └── 飞书连接器（审批卡片、通知；只做入口与出口）

 Teleport CE（MacBook，auth + proxy，经 frp 暴露）
        ├── tbot：为 Agent 签发 / 自动续期 15 分钟证书
        └── node agent：装在各目标机（macmini、生产服务器）

 macmini
        ├── 采集器（launchd）── POST /api/ingest
        └── Teleport node agent
```

关键分工：状态与权力在控制面，IM 只是输入输出口。飞书里出现的每条记录都能在控制台点开；控制台里发生的事只有需要人知道的才推飞书。

## 3. 目录组织规范

- 遵循仓库根 CLAUDE.md §2;新增顶层目录需先在此登记
- `workspace/` 为宿主机持久化数据,gitignore 不入库

## 4. 数据模型

一期核心表（M1 细化到字段与接口）：

| 表 | 用途 |
|----|------|
| `task` | 任务主记录：下发人、承接、轮次、阶段、产出、耗时、成本 |
| `a2a_message` | Agent 间往返消息（系统内通道，不经群） |
| `capability` | 授权请求、凭证、吊销与审计 |
| `agent_run` | 运行态事件流，支撑总览与任务下钻 |

纪律：schema 迁移 forward-only，禁止手改已应用迁移；「没进控制台库 = 没发生」；不使用黑板，不做投影。

## 5. 部署架构

- 本地开发：控制台进程 + SQLite，监听 127.0.0.1:8787
- 公网访问：既有 frp 部署；本项目只负责 ① 只绑 127.0.0.1、不处理 TLS；② 提供 `/healthz`；③ 交付 frpc 配置片段（local_port / custom_domains / transport.tls）
- 登录：一期固定口令；二期飞书网页应用免登
- 备份：复制 SQLite 库文件到 `workspace/backups`

## 6. 关键决策记录

| 日期 | 决策 | 理由 |
|------|------|------|
| 2026-10-29 | 初始技术选型 Node.js + TypeScript + SQLite | 单机优先、零外部依赖、宿主机可直接备份 |
| 2026-10-29 | 控制台 + 飞书双面并存，不替代 IM | 状态与权力放控制面，IM 只做输入输出口 |
| 2026-10-29 | 事实源迁到控制台库，黑板降为单向投影 | 黑板无事务与并发控制，承受不了高频写入 |
| 2026-10-29 | 停用黑板，取消投影 | 黑板实际未使用，删除可消灭双源与对账问题 |
| 2026-10-29 | 跨机复用 frp；每台机部署采集器 | 不引入第三方组网；采集器贴近数据源，负责文件增量读取与心跳 |
| 2026-10-29 | 授权采用 Teleport CE + tbot | 行业成熟方案，免自研证书签发、续期与吊销 |
