# 前端设计

> 创建日期: 2026-10-29
> 上位文档: [00-总体架构设计.md](./00-总体架构设计.md)。接口契约见 [01-后端服务设计.md](./01-后端服务设计.md)。

## 1. 形态总览

单页应用（SPA），一期内含四个页面。桌面与手机共用一套路由与组件，只做布局降级，不做两套代码。

```
┌───────────────────────────────────────────────────────────────┐
│ ┌──────────┐                                                  │
│ │ 侧边导航 │   页面区                                          │
│ │  总览    │   ┌──────────────────────────────────────────┐   │
│ │  任务    │   │ 页头：标题 · 筛选 · 刷新状态              │   │
│ │  授权    │   ├──────────────────────────────────────────┤   │
│ │  知识    │   │ 主体：表格 / 卡片 / 列表                  │   │
│ │          │   │                                          │   │
│ │  待确认② │   └──────────────────────────────────────────┘   │
│ └──────────┘                                                  │
│                                                               │
│        任务行点击 ──▶ 右侧抽屉（事件时间线 + A2A 线程）        │
└───────────────────────────────────────────────────────────────┘
```

- 桌面：左侧固定导航，主区可下钻到抽屉。
- 手机：导航收成一行横向 Tab，待确认数量以角标显示；抽屉改为全屏页。
- 不做对话主入口、不做消息流、不做长文编辑——这些属于飞书。

## 2. 技术栈

| 项 | 选择 | 状态 |
|----|------|------|
| 框架 | React 19.3.1（TypeScript 6.0.3 全仓共用，根已装） | **已定**（M3 装入） |
| 构建 | Vite 8.3.5 + @vitejs/plugin-react 6.1.2 | **已定**（M3 装入） |
| 路由 | React Router 8.5.1 | **已定**（M3 装入） |
| 服务端状态 | TanStack Query 5.105.0（缓存、重试、失效） | **已定**（M3 装入） |
| 本地状态 | 组件内 state 为主，不引入 Zustand | **已定** |
| 样式 | CSS Modules（不选 Tailwind） | **已定** |
| 图表 | 一期不引入图表库；总览用数字卡与迷你条 | 已定 |
| 测试 | Vitest 5.0.5 + Testing Library；关键路径 Playwright 1.64.1 | **已定**（Vitest 已装根；Testing Library / Playwright 于 M3 装入） |

> M1-4（2026-10-30）定稿：以上版本经 npm 校验可解析，落地时机见括号；整体裁决口径见 [00](./00-总体架构设计.md) §4。
> 不引 Zustand 的理由：四屏的跨组件状态只有「当前用户 / 筛选条件 / SSE 连接」，组件内 state 加 TanStack Query 缓存足够，多一层 store 只会多一份同步负担。

**不引入 UI 组件库**：四屏规模、表格与状态徽标为主，自建组件更省。若组件数量超过 20 个再评估。

## 3. 路由

| 路径 | 页面 | 说明 |
|------|------|------|
| `/` | 重定向到 `/overview` | — |
| `/overview` | 总览 | 登录后默认页 |
| `/tasks` | 任务列表 | 支持 `?status=&project=&assignee=` |
| `/tasks/:id` | 任务详情 | 桌面为抽屉，手机为整页 |
| `/capabilities` | 授权 | `?view=pending\|active\|history` |
| `/knowledge` | 知识 | 列表 + 详情 |
| `/knowledge/:id` | 知识条目 | — |
| `/login` | 登录 | 未登录统一跳转，回跳原路径 |

- 未知路径回 `/overview`，不显示空白页。
- 所有筛选条件反映到 URL query，保证刷新与分享后状态一致。

## 4. 页面设计

### 4.1 总览

一屏回答「谁在跑、跑到哪、花了多少」。

| 区块 | 内容 |
|------|------|
| 顶部指标 | 运行中 Agent 数、运行中任务数、今日成本、待确认数 |
| Agent 列表 | 一行一 Agent：机器、项目、当前任务、状态、最近事件、今日 token / 花费 |
| 空态 | 无 Agent 在线时给出「采集器未上报」的排查提示，不显示假数据 |

状态用颜色 + 文本双编码（不能只靠颜色区分），离线超过 5 分钟标注「心跳超时」。

Agent 注册与密钥轮换放在这里：总览本来就是 Agent 列表，点行内「密钥」入口即可注册新 Agent 或轮换。新密钥**只显示一次**，弹窗必须写明「关闭后不可再查看」，不提供复制历史。

**可见性说明常驻一行**（有数据、无数据都显示）：「控制台只看到自报的与自己的会话，看不到不属于它的飞书对话。」这是产品形态决定的边界，不是加载失败——不能因为行数少就让人以为数据缺了。

### 4.2 任务

| 区块 | 内容 |
|------|------|
| 列表 | 一行一任务：下发人、承接、轮次、阶段、产出、耗时、成本 |
| 筛选 | 状态、项目、承接方、时间范围 |
| 详情抽屉 | 事件时间线（按 seq）、A2A 往返线程、关联凭证与成本明细 |

「卡在哪一环」由时间线直接回答：最后一条事件 + 阻塞原因 + 已等待时长。

**列表页脚固定一行**：「仅显示已自报的任务——Agent 判断不需要建单的活不会出现在这里。」条数不代表全部工作量，不能让读者把它当成全量。

A2A 线程数据来自 `GET /api/tasks/:id/a2a`：按 `thread_id` 分组、组内按 `round` 升序，展示 `from → to`、`intent`、`summary`、`expect`、`deadline`、投递状态（pending / delivered / failed / uncertain）与 ACK 时间。线程状态（`open` / `awaiting_reply` / `completed` / `expired`）由服务端现算后随数据返回，**前端不自行推断**，否则会出现「消息已完结、界面还挂着等待」。线程只读；重发 / 取消等人工干预尚未建模。

**链路面包屑**：抽屉顶部显示来源链，沿 `parent_task_id` 逐级上溯到链头，每级标注关系（`a2a` = 「由 X 交接」，`continuation` = 「本方续接」）。`parent_task_id` 为空即停；链头若只有 run 没有任务，显示「上游无任务记录」，**不拿 run 伪造一个任务节点**。

### 4.3 授权

三视图切换：

- **待批**：目标、动作、范围、申请人、任务、过期时间；操作只有批准 / 拒绝。
- **生效**：凭证、剩余有效期（倒计时）、绑定任务、吊销按钮。
- **历史**：状态、操作人、时间，可按任务过滤。

**委派矩阵（谁能找谁）**：一行一发起方、一列一收件方，勾选即写该发起方的 `allowed_targets_json`。默认全不勾（default deny），自己那一格恒不可勾。7 个 Agent 是 7×6 = 42 格——规模到这个量级就必须在界面上改，靠 `UPDATE` 数据库等于绕开事实源。保存即生效，不需要重启 Agent。

批准前必须展示**完整动作与范围**，不允许折叠关键字段。批准后进入 `issuing`（显示「签发中」），按钮置灰防止重复提交；签发失败转为「签发失败」并给出重试入口，不允许显示成「已生效」。

### 4.4 知识

- 列表：分类、标题、摘要、状态、更新时间；支持关键词检索，默认只列 `active`。
- 分页签：`active` / `candidate`（待采纳，带数量角标）/ `archived`。
- 详情：Markdown 渲染 + 编辑；受保护条目（`index.md`、`log.md`）只读。
- 候选采纳：展示来源任务与 Agent、摘要与正文；操作只有「采纳」与「丢弃」。采纳后转 `active` 并触发重建索引。**不提供全选批量采纳**——候选必须逐条看，否则等于让 Agent 自己决定知识库。
- 操作：编辑、删除、整库重建索引、检索测试（输入问题看召回结果与得分；语义引擎不可用时显式标注 `degraded` 与「仅关键词」）。
- 索引状态：`embedding_status` 为 `pending` / `failed` 的条目在列表打标，可单条重试。

## 5. 数据获取与实时

```
首次进入页面 ──GET 列表/聚合──▶ 渲染
                    │
                    └──GET /api/stream──▶ snapshot(revision=N)
                                              │
                                              ▼
                                         delta(revision=N+1...)
```

| 规则 | 说明 |
|------|------|
| 快照优先 | SSE 首帧必须是 `snapshot`，客户端不自行拼装初态 |
| 缺口检测 | 收到 `revision > local + 1` 时丢弃增量并重新拉快照 |
| 断线重连 | 指数退避 1s → 2s → 4s → 8s，上限 30s；重连后重新取快照 |
| 静默失败 | 连续 3 次重连失败才在页头显示「实时断开」，不弹窗打断 |
| 写后失效 | 批准 / 编辑等写操作成功后主动 invalidate 相关查询，不等推送 |
| 不轮询 | 禁止用 `setInterval` 轮询列表；实时性由 SSE 保证 |

## 6. 组件分层

```
web/src/
├── pages/           # 四个页面，只做布局与数据装配
├── components/
│   ├── layout/      # AppShell / SideNav / MobileTabBar / PageHeader
│   ├── data/        # DataTable / StatusBadge / MetricCard / EmptyState / ErrorState
│   ├── task/        # TaskRow / TaskDrawer / TimelineList / MessageThread
│   ├── capability/  # CapabilityCard / TtlCountdown / ApproveActions
│   ├── agent/       # AgentKeyDialog（注册 / 轮换，仅显示一次）
│   └── knowledge/   # KnowledgeList / CandidateQueue / MarkdownView / Editor / SearchTest
├── api/             # REST 客户端 + SSE 订阅封装
├── stores/          # 会话、UI 偏好、实时连接状态
└── shared/          # 类型、常量、格式化（时间、金额、token）
```

**封装纪律**：

1. 页面不直接 `fetch`，一律经 `api/` 层的类型化函数。
2. 数据展示组件不认识业务枚举，状态到显示文案的映射集中在 `shared/constants`。
3. 金额格式化只在一处实现：纳美元 → 展示字符串，避免各页算法不一致。
4. 空态、错误态、加载态是三件套，每个列表都必须显式处理。

## 7. 状态管理

| 状态类型 | 归属 | 工具 |
|----------|------|------|
| 服务端数据 | 缓存、失效、重试 | TanStack Query |
| 实时帧 | 增量合并到查询缓存 | SSE 订阅 + cache 更新 |
| 会话 | 登录态、过期跳转 | 轻量 store |
| UI 本地 | 抽屉开关、筛选草稿 | 组件 state |
| URL 状态 | 筛选、分页、视图切换 | 路由 query |

禁止把服务端数据复制进全局 store——会出现两份真相。

## 8. 移动适配

- 断点：`< 768px` 为移动布局。
- 导航：顶部单行横向 Tab，待确认数量用角标，不做汉堡菜单。
- 表格：移动端改为卡片列表，保留最关键三列，其余进详情。
- 抽屉：全屏页 + 返回按钮，不做底部半屏。
- 触控：可点区域不小于 44×44 px。
- 首屏预算：移动网络下 3 秒内可交互；路由级懒加载，知识页与任务详情按需加载。

## 9. 构建与托管

- `web/` 独立构建，产物 `dist/` 由后端静态托管，与 API 同源，避免跨域。
- 开发期 Vite dev server 代理 `/api` 到 `127.0.0.1:8787`。
- 环境变量只在构建期注入公开配置（如版本号），不入库任何密钥。
- 产物不提交仓库，由 `make build` 生成。
