## 1. 形态总览

单页应用（SPA），一期内含四个主导航页面。桌面与手机共用一套路由与组件，只做布局降级，不做两套代码。工作事项与 Agent 详情均为现有页面的下钻，不新增第五块主导航。

```
┌───────────────────────────────────────────────────────────────┐
│ ┌──────────┐                                                  │
│ │ 侧边导航 │   页面区                                          │
│ │  总览    │   ┌──────────────────────────────────────────┐   │
│ │  任务    │   │ 页头：标题 · 筛选 · 刷新状态              │   │
│ │  授权    │   ├──────────────────────────────────────────┤   │
│ │  知识    │   │ 主体：表格 / 卡片 / 列表                  │   │
│ │          │   │                                          │   │
│ │  待确认② │   └──────────────────────────────────────────┘   │
│ └──────────┘                                                  │
│                                                               │
│        任务行点击 ──▶ 右侧抽屉（事件时间线 + A2A 线程）        │
└───────────────────────────────────────────────────────────────┘
```

- 桌面：左侧固定导航，主区可下钻到抽屉。
- 手机：导航收成一行横向 Tab，待确认数量以角标显示；抽屉改为全屏页。
- 不做对话主入口、不做消息流、不做长文编辑——这些属于飞书。工作事项展示目标、Mandate、Assignment/Input、Handback、进展和决策；Agent 详情只读展示已采集对话，均无发送或回复入口。WorkBuddy 首版无 Run/对话/Token 采集，不显示伪造视图。
- 正常推进保持安静；界面优先呈现需要人、待验收、异常停滞和可消费结果，不把事件数量当作工作量。

> M1-4（2026-10-30）定稿：以上版本经 npm 校验可解析，落地时机见括号；整体裁决口径见 [00](./00-总体架构设计.md) §4。
> 不引 Zustand 的理由：四屏的跨组件状态只有「当前用户 / 筛选条件 / SSE 连接」，组件内 state 加 TanStack Query 缓存足够，多一层 store 只会多一份同步负担。

**不引入 UI 组件库**：四屏规模、表格与状态徽标为主，自建组件更省。若组件数量超过 20 个再评估。

> **2026-11-06 修订**：上面这条关于「组件库」的结论仍然成立（不引第三方 UI 组件库，只引 `lucide-react` 取图标——图标不是组件库），但**「四屏规模不值得有设计系统」的前提已被推翻**：控制台要从联调工具变成可长期使用的生产级产品，四屏 + 落地页 + 接入向导共 7 个界面必须有统一的设计基线与组件基元层。见 §11。

## 4. 页面设计

### 4.0 首次使用引导（`/setup`）

首次使用采用四步引导，不增加主导航，不要求用户阅读架构文档或手工编辑配置。每一步只显示必要输入与系统已完成的自动装配。

| 步骤 | 页面内容 | 用户动作 | 系统自动行为 |
|------|----------|----------|--------------|
| 1. 初始化 | 一次性 bootstrap token、管理员口令、空库与空知识说明；frp 使用既有部署配置 | 输入本机输出的 token 并设置管理员口令 | 无凭据时仅开放 bootstrap mode；初始化 PostgreSQL、扩展、迁移、知识与备份目录，执行健康检查，成功后创建会话并解锁完整控制台 |
| 2. 添加执行机 | 一次性 enroll token 与单条安装命令 | 在目标机执行命令，令牌经隐藏输入/stdin/env 提供 | 自动换取机器 ID 和采集密钥、安装 aw-node、写 launchd、启动并回传心跳与自检结果 |
| 3. 添加项目 | 执行机已上报的 cc-connect 发现结果；缺少时的项目名、仓库地址、工作目录；必要集成授权 | 选择项目并确认主责 Agent | 控制台读取已上报结果并预填，创建 agent.id/key 与**不含明文 Bearer**的待下发运行时配置，默认 `project.primary_agent`；aw-node 在配置请求中取得最新 secret，ACK 后不再返回明文 |
| 4. 启用 Bug 工作流 | Bug 来源、仓库、CI、主责 Agent、`bug_fix`、PR+CI 与原 Bug 机器人验收摘要 | 核对后点击「确认并开始使用」 | 生成 Git RouteRule、Mandate 和证据模板，aw-node 自动下载并写入运行时配置后回执；检测 Bug 提交与接受/退回、GitHub/CI、MCP、aw-node 和权限连通性 |

**预检与收尾**：

- 第 3 步按机器分组：Agent 绑定的是机器，多台执行机同时在线时**每台机各自确认自己的项目**，跨机项目不并到同一台机去确认；每组同时标出该机的心跳时间，便于分辨是哪台机在报。
- 预检按数据库、机器、采集、MCP、Agent、项目角色、Bug Source、GitHub/CI 分项展示成功、失败和未配置；失败项必须给出修复入口，不能统一显示为已就绪。
- 用户只能看到自然语言配置摘要，不需要编辑 RouteRule、Mandate、worker_inbox 或 plist；需要高级修改时仍回 Git 配置走评审，不在首版增加规则编辑器。
- 初始化成功后返回总览并提示「去原 Bug 机器人反馈第一个问题」；配置不完整则停在对应步骤，不创建空 Assignment。
- WorkBuddy 的过程数据固定显示「未接入 / —」，不作为初始化失败条件。

### 4.1 总览

一屏回答「哪些事需要我、各项目是否有实质进展、谁在跑、用了多少 token」。

| 区块 | 内容 |
|------|------|
| 顶部指标 | 运行中 Agent 数、进行中工作事项数、今日 token 消耗、需要我 / 待验收数、异常停滞与心跳超时数 |
| 注意力队列 | 只列需要决策、待验收、阻塞或异常停滞的事项；每条一次给出背景、问题、证据、选项 / 建议与下一步，无动作价值的通知不进入 |
| Agent 管理表 | 一行一 Agent 的**管理表格**（不是卡片墙）：机器人（**飞书机器人名** + 项目 + key 副行，列头带 `?` 说明）｜运行时（**图标**，悬浮 / 聚焦显示全名）｜机器（**图标 + 展示名**，列头带 `?` 说明）｜状态（心跳 + 运行 + 启停双编码）｜当前任务（标题 + 阶段 / 状态）｜今日 Token｜累计运行｜最近运行｜操作 |
| 空态 | 无 Agent 在线时给出「aw-node 未上报」的排查提示；无待办时显示「当前无需处理」，不制造提醒或假数据 |

**总览只讲 Agent**（2026-11-07 裁决）：工作事项的**列表**不再出现在总览，挪到任务屏（§4.2 的「工作事项区块」）；总览保留指标、注意力队列与 Agent 管理表，避免一屏里塞两张长表。要看事项清单的人从任务屏进，事项详情仍从任务或总览的入口下钻。

**Agent 管理表**（2026-11-06 新增）：工具条为搜索（项目 / 名称 / key）、状态筛选（启用 / 停用 / 全部）、运行时筛选与机器筛选，右侧一组列表 / 卡片切换（偏好存 `localStorage["aw:agents-view"]`，窄屏恒卡片）；行点击打开**详情抽屉**（概览 / 任务 / 对话记录三区，只读），行内「管理」按钮才打开**编辑抽屉**——可改显示名、改项目、启停、**绑定 / 解绑宿主机器**、调整委派白名单、设用量上限、轮换密钥与删除。管理动作与总览的「只读展示」共存于同一屏，但写操作一律收在抽屉里，不在表格行上直接摊开。

**Agent 详情抽屉**（2026-11-06 新增，`AgentDetailDialog` + `AgentTimeline` / `AgentOverviewPanel` / `AgentTaskPanel`）：点行（或窄屏点卡片本体）打开右侧抽屉，分三个只读标签页——「概览」展示身份档案与用量（数据全部来自既有名册行 + 总览活体状态，不发新请求）；「任务」用既有 `GET /api/tasks?assignee=<id>` 列该 Agent 承接的任务，点行跳 `/tasks/:id`；「对话记录」用新增的只读端点 `GET /api/agents/:id/timeline`（见 [01](./01-后端服务设计.md) §4）按会话分组渲染用户消息 / 助手回复 / 思考 / 工具调用 / 工具结果，可按类型过滤、按游标加载更早记录。**没有采集器的 Agent（外部运行时或未绑机）不请求对话端点，直接显示「未接入」空态**，与表格列口径一致。

- **Agent 名显示飞书机器人名**（2026-11-06 修订）：Agent 名一律用飞书 bot 名（`feishuBotName`，如 `@小工`），没有 bot 名时回退控制台 `displayName`；**不显示 cc-connect 项目名**——项目名是采集归因的技术字段，给人看的是机器人在飞书里的称呼。规则收敛在 `web/src/shared/agent-label.ts` 的 `agentDisplayName` / `agentMention`，名册、总览表格、窄屏卡片、任务抽屉与轮次链共用同一处。
- **机器列显示展示名**：`machine.displayName`（控制台可改）优先，回退 `hostname`；执行机登记时把 IP 当成机器名是既有事实，展示名让用户能把它改成「macmini」这类可读称呼（见 [01](./01-后端服务设计.md) §4.3）。
- **运行时列改产品品牌标识**（2026-11-06 修订，2026-11-07 改用真 logo）：运行时列不显示文字，直接渲染各产品**真实品牌标识**——`claude_code` 用 Anthropic 官方 sunburst（陶土橙 `#D97757`）、`workbuddy` 用腾讯 WorkBuddy 官方标识（青绿渐变 `#0EC8A9 → #01C886`）、`codex` 用 OpenAI 官方标识（蓝紫渐变 `#B1A7FF → #7A9DFF → #3941FF`）、`deepseek` 用官方鲸鱼标识（蓝 `#4D6BFE`）；标识外套 `Tooltip` 悬浮 / 聚焦显示全名并带 `aria-label`；筛选下拉仍用文字（可读性优先）。**这一条 supersede 了早先「用语义化通用图标、不引品牌 logo」的结论**——通用图标（`SquareTerminal` / `Blocks` / `Code` / `Brain`）无法让用户分辨用的是哪套 Agent 系统，改为直接用产品标识；素材来源与授权说明见 `web/src/shared/runtime-icon.tsx` 头注释（品牌名称与标识归各自权利人所有）。
- **机器列图标化 + 列头 tip**（2026-11-06 修订）：机器列显示 `Monitor` 图标 + 机器名（展示名优先回退 hostname），未绑机为灰色图标 + 「未绑定」；「机器人」「机器」两列头各带一枚 `?`（`CircleHelp` + `Tooltip`）说明该列含义，纯图标列不再靠用户猜。
- **运行归属段**（编辑抽屉）：外部运行时（WorkBuddy / Codex / DeepSeek）提供机器下拉，可绑可解绑；`claude_code` 的机器绑定只读（采集与调度依赖本机 aw-node，不允许解绑）。**绑定只登记宿主归属，不产生过程数据**——外部运行时永远显示「未接入 / —」。绑定同时让该 Agent 能按 `(machine_id, project)` 匹配到飞书 bot 名。
- 表格列宽固定（`table-layout: fixed`），长 id 与长 URL 由单元格自身截断，桌面宽度下不出现横向滚动条；窄屏转卡片（§8）。
- **「当前任务」列按三态显示**（2026-11-06 修订）：有任务归属时显示任务标题 + 阶段 / 状态；运行中但未建单（`run.task_id` 为空，如 cc-connect 直接驱动的会话）时显示「最近指令」——取该 run 最近一条真实用户指令（`currentInstruction`），用一句话回答「在忙什么」，不能因为没有任务标题就显示空横杠；两者都没有时显示「当前没有进行中的任务」。
- **有没有过程数据看两个条件**（2026-11-06 修订）：`runtime='claude_code'` 且 `machine_id` 非空才有 Run / 对话 / Token。外部运行时即便登记了宿主机器也固定显示「未接入 / —」，不得显示为 0 或「从未运行」。
- 抽屉是唯一写入口：表单有 label、有提示、有错误态，提交期间按钮禁用并给出「保存中…」反馈。
- **删除必须先看影响清单**：确认前调用 `GET /api/agents/:id/delete-impact` 拉三组计数——`destroyed`（随 Agent 一起删掉的行）、`detached`（引用被置空但事实保留）、`retained`（原样保留，如任务与审计日志）；文案按「整条 A2A 线程」口径而非「该 Agent 的消息」。删除是不可逆操作，界面必须明确写出这一点。
- 删除后列表立即少一行，`GET /api/overview` 的该 Agent 同时消失；被删 Agent 的历史引用显示为「已删除 Agent X」（墓碑，见 [01](./01-后端服务设计.md) §4.2），不显示裸 id。

状态用颜色 + 文本双编码（不能只靠颜色区分），离线超过 5 分钟标注「心跳超时」。工作事项的 `attention`、阶段和等待原因由服务端返回，前端不按最后一条消息自行猜测。

Agent 注册与密钥轮换放在这里：初始化通过 `/setup` 自动发现并生成 Agent，总览仅用于后续新增 Agent 与轮换。新密钥**只显示一次**，弹窗必须写明「关闭后不可再查看」，展示后不允许点遮罩 / Esc 误关，不提供复制历史。

**添加执行机**也统一走一次性 enroll token：页面只生成令牌和单条安装命令，不再要求填写 `collector_id`、主机名、OS 或版本。aw-node 自动登记并上报发现结果后，用户只确认项目与主责 Agent；登记和配置回执未完成前，该机推送的流一律按未归因处理。

**机器无关运行时空态**：外部运行时（WorkBuddy/Codex/DeepSeek harness）其 Task、A2A、Assignment 和产出可正常展示；Run、对话与 Token 固定显示「未接入 / —」，不得显示为 0、离线或采集失败，也不提供伪造的对话视图。此类 Agent 同样以飞书机器人名优先命名；未绑定机器时副行显示「项目 · 运行时」（如 `wb-proj · WorkBuddy`），绑了机器则并列机器展示名。

**机器改名入口**（2026-11-06 新增）：接入向导的「已上线机器」列表与总览机器列都提供改名入口，弹窗改的是 `machine.displayName`（`PATCH /api/machines/:id`），不动 `hostname`（enroll 去重键）。改名即时生效，不影响已绑定的 Agent 与采集归因。

**可见性说明常驻一行**（有数据、无数据都显示）：「仅展示已自报任务与已成功采集的会话，不承诺全量飞书或历史可见。」这是产品形态决定的边界，不是加载失败——不能因为行数少就让人以为数据缺了。

### 4.2 任务

| 区块 | 内容 |
|------|------|
| 列表 | 一行一任务：下发人、承接、轮次、阶段、产出、耗时、token 消耗 |
| 筛选 | 状态、项目、承接方、时间范围 |
| 工作事项区块 | 平铺的事项清单（列「事项 / 项目 / 阶段 / 注意力 / 下一步 / 更新」），带注意力筛选与加载更多 |
| 详情抽屉 | 所属工作事项入口、事件时间线（按 seq）、A2A 往返线程、关联凭证与 token 明细 |

「卡在哪一环」由时间线直接回答：最后一条事件 + 阻塞原因 + 已等待时长。

**列表页脚固定一行**：「仅显示已自报的任务——Agent 判断不需要建单的活不会出现在这里。」条数不代表全部工作量，不能让读者把它当成全量。

**工作事项区块**（2026-11-07 新增，同年 11-07 挪到任务屏）：任务列表下方的一张**平铺列表**（非按项目分组），是 §4.3 事项详情的入口。列「事项 / 项目 / 阶段 / 注意力 / 下一步 / 更新」；顶部 `ChipGroup` 按服务端 `attention` 筛选（全部 / 需要人 / 待验收 / 阻塞 / 异常停滞），筛选态进 URL `?wi=<attention>`（服务端筛选，客户端筛会被默认分页截断）；首屏 `limit=20` + 「加载更多」。注意力 `person > blocked > acceptance > stalled > none` 优先、同级按 `updatedAt` 倒序重排，把要人处理的事浮到最上。行点击进 `/work-items/:id` 抽屉，抽屉**叠在任务列表之上**（两者共用任务屏布局），关闭后回到 `/tasks` 并保留筛选。窄屏转卡片（§8）。区块页脚固定一行：「仅展示已由触发事实路由出的工作事项——没被路由的活不会出现在这里。」

A2A 线程数据来自 `GET /api/tasks/:id/a2a`：按 `thread_id` 分组、组内按 `round` 升序，展示 `from → to`、`intent`、`summary`、`expect`、`deadline`、投递状态（pending / delivered / failed / uncertain）与 ACK 时间。线程状态（`open` / `awaiting_reply` / `completed` / `expired`）由服务端现算后随数据返回，**前端不自行推断**，否则会出现「消息已完结、界面还挂着等待」。线程只读；重发 / 取消等人工干预尚未建模。

**轮次链按飞书机器人名显示**（2026-11-06 修订）：抽屉标题的「下发 → 承接」、摘要区的「下发 / 承接」两行、A2A 线程的 `from → to` 一律用 `@机器人名`（飞书 bot 名，没有则回退 `displayName`），与群里的称呼一致；**不显示 cc-connect 项目名**（那是采集归因字段）。名册外的 Agent 回退服务端给的标签（如「已删除 Agent X」），不硬加 `@`，也不显示裸 id 串。

**链路面包屑**：抽屉顶部显示来源链，沿 `parent_task_id` 逐级上溯到链头，每级标注关系（`a2a` = 「由 X 交接」，`continuation` = 「本方续接」）。`parent_task_id` 为空即停；链头若只有 run 没有任务，显示「上游无任务记录」，**不拿 run 伪造一个任务节点**。任务责任链与所属工作事项是两个维度：面包屑回答「谁交给谁」，事项入口回答「共同为哪个业务结果工作」。

### 4.3 工作事项详情（下钻，不是第五屏）

| 区块 | 内容 |
|------|------|
| 目标与边界 | 来源、业务项目、预期结果、不可变 Mandate、当前策略版本；人可核对「为什么可以做、做到什么程度」 |
| 当前状态 | 阶段、注意力状态、等待对象、下一步、最近实质进展与停滞证据；等待人不显示为异常空转 |
| 关联工作 | 关联 Task、Run、Assignment/Input、Handback、Bug/PR/CI Thread 与 A2A 引用；Task/Run 为零时如实展示，不补假节点 |
| 结果与验证 | 可访问产出、PR / CI / 评审依据、未完成事项与已知限制；生产发布仍是独立人工动作 |
| 永久时间线 | 工作事项事件按 `seq` 展示；原始消息、文档和证据按需打开，摘要不可用时仍能追溯来源 |

- 页面只读呈现协调事实；需要批准、发布或补充需求时跳转既有授权 / 飞书入口，不在事项详情内新增聊天框。真实 Bug 的人工接受/退回只在原 Bug 机器人完成。
- 路由记录展示确定性 `RouteRule ID + Git 版本 + disposition + reason_code`，不能伪装成人的决定；真实 Bug 还需展示 PR 当前 head 的 CI、待验收时间、原 Bug 机器人的接受或退回记录。
- 正常推进的事项无需弹出提醒；同一停滞在同一 `progress_revision` 下只提醒一次，有新证据后才允许更新提醒。

### 4.4 授权

三视图切换：

- **待批**：目标、动作、范围、申请人、任务、过期时间；操作只有批准 / 拒绝。
- **生效**：凭证、剩余有效期（倒计时）、绑定任务、吊销按钮。
- **历史**：状态、操作人、时间，可按任务过滤。

**委派矩阵（谁能找谁）**：一行一发起方、一列一收件方，勾选即写该发起方的 `allowed_targets_json`。默认全不勾（default deny），自己那一格恒不可勾。7 个 Agent 是 7×6 = 42 格——规模到这个量级就必须在界面上改，靠 `UPDATE` 数据库等于绕开事实源。保存即生效，不需要重启 Agent。

批准前必须展示**完整动作与范围**，不允许折叠关键字段。批准后进入 `issuing`（显示「签发中」），按钮置灰防止重复提交；签发失败转为「签发失败」并给出重试入口，不允许显示成「已生效」。

### 4.5 知识

- 列表：分类、标题、摘要、状态、更新时间；支持关键词检索，默认只列 `active`。
- 分页签：`active` / `candidate`（待采纳，带数量角标）/ `archived`。
- 详情：Markdown 渲染 + 编辑；受保护条目（`index.md`、`log.md`）只读。
- 候选采纳：展示来源任务与 Agent、摘要与正文；操作只有「采纳」与「丢弃」。采纳后转 `active` 并触发重建索引。**不提供全选批量采纳**——候选必须逐条看，否则等于让 Agent 自己决定知识库。
- 操作：编辑、删除、整库重建索引、检索测试（输入问题看召回结果与得分；语义引擎不可用时显式标注 `degraded` 与「仅关键词」）。
- 索引状态：`embedding_status` 为 `pending` / `failed` 的条目在列表打标，可单条重试。

### 4.6 接入执行机（`/onboarding`）

总览页的下钻页，独立路由，不是第五块主导航。目的是让「把一台机器接进来」变成一条有步骤、有状态、有校验的流程，而不是一段裸命令加一个链接。

| 步骤 | 页面内容 | 关键约束 |
|------|----------|----------|
| 1. 下载产物 | 按平台分卡（macOS arm64 / x64 等），自动识别当前平台并标记「推荐」；每卡含体积、完整 SHA-256（界面截断显示，可一键复制全量）、下载按钮、复制直链、复制校验和 | 校验和缺失时显式写「控制台未提供校验和」，不编造 |
| 2. 安装执行机 | 编号四步：执行安装命令 → 脚本提示时粘贴一次性 token → 写 launchd → 自检；每步一段说明 + 一个可复制代码块；另给手动安装备选路径（下载二进制 → `chmod +x` → `aw-node enroll`） | **安装命令与令牌分开展示**：令牌不出现在命令行参数里，粘贴时输入不回显，也不进 shell history |
| 2b. 覆盖安装 | 单独一块，给「这台机已经加入过」的路径：一条带 `--mode upgrade` 的可复制命令，说明不需要一次性 token、不换机器身份、既有的 launchd 环境变量原样保留 | 覆盖安装与首次加入是两种语义，页面必须分开给出，不能让用户为了升级去重新签发令牌 |
| 3. 令牌与上线 | 签发按钮 → 令牌一次性展示 + 15 分钟倒计时（归零显示「已过期，请重新签发」）；下方列出已上线机器（心跳、发现上报时间、项目数） | 页面不回显历史令牌；倒计时走字可见 |

- 复制类操作统一走 `CopyField` / 复制按钮 + toast 反馈，不做「点了没反应」。
- 令牌与安装命令都不进 URL、不进日志、不入前端持久化存储。
- **执行机清单同时承担项目登记入口**：机器行按「心跳」与「发现上报」两个不同源的时间分别显示（心跳是 aw-node 存活上报，发现是 cc-connect 扫描结果，不得混用）；未登记的项目列在「待登记项目」里，默认全选、可逐项取消，按机器提交「登记为 Agent」（`POST /api/bootstrap/agents`）。Agent 绑定的是机器，因此登记必须按机器分开提交——跨机项目不能并到同一台机去确认。控制台初始化完成后 `/setup` 不再可进第 3 步，新接的机器只能从本页登记项目。



## 5. 数据获取与实时

```
首次进入页面 ──GET 列表/聚合──▶ 渲染
                    │
                    └──GET /api/stream──▶ snapshot(revision=N)
                                              │
                                              ▼
                                         delta(revision=N+1...)
```

| 规则 | 说明 |
|------|------|
| 快照优先 | SSE 首帧必须是 `snapshot`，客户端不自行拼装初态；`overview`、`task:<id>`、`work_item:<id>` 分别维护自己的 revision |
| 缺口检测 | 收到 `revision > local + 1` 时丢弃增量并重新拉快照 |
| 断线重连 | 指数退避 1s → 2s → 4s → 8s，上限 30s；重连后重新取快照 |
| 静默失败 | 连续 3 次重连失败才在页头显示「实时断开」，不弹窗打断 |
| 写后失效 | 批准 / 编辑等写操作成功后主动 invalidate 相关查询，不等推送 |
| 不轮询 | 禁止用 `setInterval` 轮询列表；实时性由 SSE 保证 |

## 6. 组件分层

```
web/src/
├── pages/           # 七个页面，只做布局与数据装配
├── components/
│   ├── ui/          # 组件基元层（§10.2）：Button / Field / Table / Dialog / Menu / StatCard …
│   ├── brand/       # LogoIcon：品牌标识
│   ├── layout/      # AppShell / ThemeToggle
│   ├── machines/    # 跨页共用：执行机项目勾选语义（接入页与首次使用引导共用）
│   ├── setup/       # SetupStepper / StepAdmin / StepProjects / StepBugfix / StepDone
│   ├── onboarding/  # DownloadStep / InstallStep / EnrollTokenPanel / OnlineMachines
│   ├── task/        # TaskTable / TaskDrawer / TaskTimeline / TaskA2aThreads
│   ├── work/        # AttentionQueue / WorkItemDrawer / WorkerInbox / ProgressEvidence / ValidationRefs
│   ├── capability/  # CapabilityCard / DelegationMatrix / TtlCountdown / ApproveActions
│   ├── agents/      # AgentManagementTable / AgentCardList / AgentDetailDialog / AgentTimeline / AgentEditDialog / AgentDeleteDialog / AgentKeyDialog
│   └── knowledge/   # KnowledgeList / CandidateQueue / MarkdownView / Editor / SearchTest
├── api/             # REST 客户端 + SSE 订阅封装
├── stores/          # 会话、UI 偏好、实时连接状态
└── shared/          # 类型、常量、格式化（时间、token）、主题
```

**封装纪律**：

1. 页面不直接 `fetch`，一律经 `api/` 层的类型化函数。
2. 数据展示组件不认识业务枚举，状态到显示文案的映射集中在 `shared/constants`。
3. token 格式化只在一处实现：千分位；超过 1M 用 `1.2M` 缩写，精确值放 `title` 或抽屉，避免各页算法不一致。
4. 空态、错误态、加载态是三件套，每个列表都必须显式处理。
5. **基元层不反向依赖业务层**：`components/ui/` 不 import `api/` 与 `shared/labels`，只消费纯展示属性（如 `error: string | null`），因此基元可以被单测独立渲染。
6. 样式一律走 CSS Module + 全局令牌，不在组件里写死颜色、间距与字号。

## 7. 状态管理

| 状态类型 | 归属 | 工具 |
|----------|------|------|
| 服务端数据 | 缓存、失效、重试 | TanStack Query |
| 实时帧 | 增量合并到查询缓存 | SSE 订阅 + cache 更新 |

禁止把服务端数据复制进全局 store——会出现两份真相。

## 9. 构建与托管

- `web/` 独立构建，产物 `dist/web`（仓库根下）由后端静态托管，与 API 同源，避免跨域。

## 10. 设计基线与组件基元

2026-11-06 起控制台按生产级产品重做，本章是这次重做的基线约定。裁决背景见 [06-架构评审记录.md](./06-架构评审记录.md) §17。

### 10.1 设计令牌

令牌全部集中在 `web/src/global.css` 的 `:root`，明暗两套值同名覆盖。**组件里不写死颜色、间距、圆角、字号与动效时长**，一律引用令牌。

色板对齐 SquadSight 的设计语言（2026-11-07 修订）：主色靛蓝 `--accent: #5e6ad2`（深色下提亮到 `#6e78dd` 以保住对比度），语义色成功 `#2ea043` / 警告 `#d29922` / 危险 `#f85149` / 信息 `#58a6ff`，底色分 `--bg` / `--surface` / `--surface-2` / `--surface-3` 四层。

| 组 | 令牌 | 取值 |
|----|------|------|
| 间距 | `--space-1..7` | 4 / 8 / 12 / 16 / 24 / 32 / 48 px |
| 圆角 | `--radius-xs/sm/md/lg/full` | 4 / 6 / 8 / 12 / 999 px |
| 阴影 | `--shadow-xs/sm/md/lg` | 四级浮起阴影（原全站无阴影） |
| 字号 | `--font-2xs/xs/sm/md/lg/xl/2xl` | 10 / 12 / 13 / 14 / 16 / 20 / 24 px；另有 `--font-mono` |
| 字距 | `--tracking-tight`、`--tracking-wide` | .03em / .06em（微标签与表头用） |
| 动效 | `--duration-fast/--duration`、`--ease` | 120 / 160 ms；`cubic-bezier(.2,.6,.3,1)` |
| 焦点 | `--focus-ring`、`--danger-focus` | 键盘焦点环 / 危险态焦点环，所有可聚焦元素统一 |
| 控件尺寸 | `--size-control-sm/md/lg` | 28 / 34 / 42 px |
| 触控与图标 | `--size-touch`、`--size-icon-tile`、`--size-avatar`、`--size-textarea`、`--size-empty-icon` | 44 / 22 / 32 / 84 / 64 px（空态圆形图标底座） |
| 布局 | `--sidebar-w`、`--topbar-h`、`--content-max`、`--content-narrow`、`--content-prose` | 220 / 52 / 1440 / 1100 / 720 px |
| 面板与浮层 | `--dialog-sm/md/lg/xl`、`--drawer-w`、`--toast-w-min/max`、`--menu-w-min`、`--tooltip-w-max` | 420 / 560 / 760 / 1040、720、200 / 360、190、280 px |

字号基线从 `base font-size: 13px` 调整为：**正文 14 px、表格 13 px、元信息 12 px**（中文界面 13 px 正文偏小）。状态一律颜色 + 文字双编码，不靠颜色单独区分。

**写死数值的边界**（2026-11-07 裁决）：颜色、间距、字号、圆角、控件与触控尺寸一律走令牌；**结构尺寸留在各模块内**——栅格轨道最小宽（150 / 180 / 280 / 360 px）、滚动区上限（220 / 320 px）、文本截断宽度（60 / 84 / 160 / 180 px）语义各不相同，塞进共享令牌只会造成「同名不同义」。允许保留的裸值只有 `1px` 边框、`767px` 断点与 `44px` 触达底线（后者改用 `--size-touch`）。

### 10.2 组件基元层

`web/src/components/ui/` 是一层与业务无关的基元，共 23 个文件：

`Button`（primary / secondary / ghost / danger × sm / md / lg，loading 态与 icon 槽）、`IconButton`（含 ghost 变体）、`Field`（label + hint + error 表单壳，内含 `Input` / `Textarea` / `Select`）、`Badge`（语义 tone）、`Panel`、`Table`（`fixedLayout` / `nowrap` / `rowHeader` / `plain`）、`Dialog`（portal + 焦点陷阱 + drawer / center 两型）、`Menu`（非模态下拉菜单，portal + Esc + 外部点击关闭）、`Toast`（Provider + `useToast`）、`Tabs`、`Chip`（筛选组）、`Skeleton`、`EmptyState`、`ErrorState`、`LoadingState`、`StatCard`、`SectionHeader`、`PageFooter`、`ToneIcon`、`CopyField`、`Stepper`、`AsyncSection`、`Tooltip`（CSS 悬浮提示）。品牌标识另置 `components/brand/LogoIcon`。

约束：

- 基元不 import `api/` 与业务映射；错误态由调用方以 `error: string | null` 传入，因此基元可独立单测。`Tone` 类型因此从 `shared/labels` 迁到 `shared/tone`，`labels` 改为 re-export 保持既有 import 路径不破。
- 基元数量 23 < 20 的上限已超（20 是「再评估是否引第三方组件库」的阈值，不是硬上限）；**不引第三方 UI 组件库**这条仍然成立——自建基元换来的是令牌一致与语义可控，引库反而要再写一层适配。图标取自 `lucide-react`（图标不是组件库）。
- `Tooltip` 是全站第一个浮层原语：纯 CSS `:hover` / `:focus-within` 显隐，触发元素是 `<button>`（键盘可达），气泡用 portal 定位避免被 `.tableWrap { overflow-x: auto }` 裁剪；目前只服务列头提示一种场景，不做通用浮层库。
- `Table` 支持 `fixedLayout`：列宽严格按声明生效，长 id / URL 由单元格自身截断，桌面宽度下不出现横向滚动条；窄屏由页面层转卡片。`plain` 列选项让实体名（人名、Agent 名）不受表头大写微标签样式影响。
- **CSS Module 类名守门**（`components/ui/css-modules.test.tsx`）：vitest 未开 `css: true`，`styles.X` 在测试里恒为 `undefined`，类名拼错不会报错、只在浏览器里静默失效（`.emptyIcon` 曾这样漏过一轮）。守门测试扫源码比对「组件引用的 `styles.X`」与「对应 `.module.css` 里真实存在的规则」，引用了却没定义即失败。

### 10.3 主题

- `:root` 为浅色；`:root[data-theme="dark"]` 为深色；`@media (prefers-color-scheme: dark)` 下 `:root:not([data-theme="light"])` 跟随系统。
- 偏好存 `localStorage["aw:theme"]`，由 `shared/theme.tsx` 的 `ThemeProvider` / `useTheme` 持有；顶栏切换开关在明亮与暗黑之间直接来回（`toggleTheme`），下拉菜单另提供「跟随系统 / 明亮 / 暗黑」三选。
- 深浅两套值语义同名，组件不感知当前主题。

### 10.4 应用外壳与响应式

- **侧栏 220 px**：浅色同族底（`--surface`）+ 1 px 边框，与内容区同族而不割裂；品牌区（LogoIcon + 名称 + 副名）、两组导航微标签（「工作台」：总览 / 任务；「治理」：授权 / 知识）、底部环境标签与版本号。**选中态是 `--surface-2` 底色块 + 强文字色**，不是深色药丸。
- **顶栏 52 px**：左侧页面标题 + 一句说明；右侧依次是实时状态徽标 → 明亮 / 暗黑切换开关 → 用户头像菜单（账号信息 + **修改口令** + 外观三选 + 退出登录）。退出登录只在用户菜单里出现一处。
- **修改口令弹窗**（2026-11-07 新增）：三个输入（当前口令 / 新口令 / 确认新口令），本地先校验长度与两次一致，再打 `POST /api/auth/password`。**改完不踢当前设备下线**——服务端只吊销其他设备的会话，成功提示里带上被吊销的会话数（`口令已更新,已吊销 N 个其他设备的登录态`）；服务端说当前口令不对时原样显示，不清空表单。
- 内容区最大 1440 px，页面内容收敛到 `--content-narrow` 1100 px；长文（知识正文）限 `--content-prose` 720 px 保证可读行长。分区用 `--surface` + 1 px 边框 + 8~12 px 圆角 + `--shadow-sm`。
- 指标卡栅格用 `repeat(auto-fit, minmax(180px, 1fr))`，卡片数量变化时不留孤行卡。
- `< 768px`：侧栏收成顶部横排 Tab（分组标签隐藏，触达区抬到 44 px）；**导航独占一行**——品牌区与环境标签留在上一行，否则 375 px 下环境徽标会把右侧导航项挤出可视区；表格转卡片；抽屉转全屏；可点区域不小于 44×44 px（断点规则写在 `global.css`，各组件不再各自为政）。
