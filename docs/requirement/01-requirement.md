# agent-workbench 需求基准

> 创建日期: 2026-10-29
> 本文档是需求基准(变更需谨慎并记录原因);范围之外的一律进「明确不做清单」。
> 原始需求快照见 [02-requirement-v0.7.md](02-requirement-v0.7.md)(飞书原文导出,2026-10-29)。

## 1. 项目定位

把散落在飞书群、黑板表格、本地脚本里的多 Agent 协作，收进一个可看、可控、可计量的工作台——人能看清 Agent 在干什么，系统能拦住它不该干的事，账上能算清花了多少。

**目标用户**: 持有多个 Agent（WorkBuddy / cc-connect+Claude Code）的个人开发者（当前唯一用户：诸葛东明）。

**核心价值**: 当前协作栈（cc-connect + 飞书群 + 黑板表格 + 规范文档）跑通了 A2A，但状态不可见、知识用不上、约束停在纸面。控制台补的是控制面，不替换飞书。

### 1.1 产品形态：控制台 + 飞书双面并存

- 控制台管「状态与权力」：运行态、任务、授权、知识
- 飞书管「说话与拍板」：下任务、看结论、一键批准/拒绝
- 控制台不承担 IM 功能：不做对话主入口、不做长文讨论、不做消息流
- 一期四屏：总览 / 任务 / 授权 / 知识

## 2. 分期功能范围

> 术语统一：**MVP** = M3（总览 + 任务，只读）；**一期** = M1.5 ~ M3.5 合集（四屏可用、授权生效）；**二期** = M4 及后置池。
> 里程碑编号与顺序采用需求原文 §11 方案，状态见 `docs/plan/development-plan.md`。

### 一期（含 MVP 及其前置，必须交付）

| # | 功能 | 说明 | 优先级 | 里程碑 |
|---|------|------|--------|--------|
| 1 | 总览屏 | 一行一 Agent：机器、项目、当前任务、状态、最近事件、今日 token/花费；3 秒内看清谁在跑、跑到哪、花了多少 | P0 | M3 |
| 2 | 任务屏 | 一行一任务：下发人、承接、轮次、阶段、产出、耗时、成本；可下钻到事件与 A2A 线程 | P0 | M3 |
| 3 | 授权屏 | 待批请求、生效凭证、历史审计；批准/拒绝/吊销 | P0 | M3.5（能力 M2 先行） |
| 4 | 知识屏 | kb 条目浏览、编辑、候选采纳、索引重建与检索测试 | P1 | M3.5 |
| 5 | 工具调用闸门 | 分类、拦截、审批、审计四件事（先覆盖本机 Agent） | P0 | M2 |
| 6 | 成本度量 | token 记账与预算控制，按 Agent 与项目统计 | P1 | M4 |
| 7 | 事实源 | 控制台库为唯一事实源；不使用黑板、不做投影（原「事实源与投影」取消投影部分） | P0 | M3 |

| # | 功能 | 触发条件 | 里程碑 |
|---|------|----------|--------|
| 1 | 飞书网页应用嵌入（免登录） | 一期口令登录稳定运行后 | M4 |

## 3. 明确不做清单

- 不做多租户 SaaS，不做对外商业化
- 不重写 Agent 运行时（Claude Code / cc-connect 是资产）
- 不做像素风 / 游戏化可视化
- 不接入 20+ 消息渠道；人机交互只用飞书，Agent 往返走系统内通道
- 不做自建 IM、移动端原生 App、跨组织账号体系
- 不做飞书黑板表格投影（黑板已停用，2026-10-29 裁决）
- 本期不替换 cc-connect

## 4. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 控制台首屏 3 秒内回答「谁在跑、跑到哪、花了多少」；飞书 API 刷新间隔 ≥ 30 秒，看板走本地缓存 |
| 安全 | 控制台只绑 127.0.0.1:8787，不自己处理 TLS；一期口令登录；凭证由 Teleport CE + tbot 签发，TTL 15 分钟、自动续期、可追溯到任务；吊销以 TTL 自然过期为主；密钥仅 env，永不入库明文 |
| 可用性 | 飞书链路保持可用，人手机上一句话仍能下任务与批复；单机部署，不依赖第三方账号 |
| 备份 | SQLite 库落 workspace/，备份=复制库文件到 workspace/backups |
| 移动端 | 手机浏览器可访问；导航收成一行，待确认入口进导航栏 |

## 5. 验收标准

- 总览：打开 3 秒内看清所有 Agent 在干什么
- 任务：任一任务能回答「卡在哪一环」
- 授权：生产资源零长期凭证；短时证书 TTL 15 分钟且自动续期；审计可追溯 task_id
- 知识：同一问题第二次不再重复解释
- 沟通：缺字段的消息被拒收，一发通过率 ≥ 60%
- 产出：任务闭环率、耗时、返工、产出物、成本可按 Agent 与项目统计

## 6. 与原文的差异裁决（2026-10-29）

需求原文 `02-requirement-v0.7.md` 保留了 v0.4 → v0.7 的演进痕迹，存在旧口径残留与内部冲突。本节是唯一裁决记录，原文对应位置已在文首「勘误」标注。

| # | 冲突 | 裁决 | 依据 |
|---|------|------|------|
| 1 | 事实源：§3.2 硬规则 3「没进黑板 = 没发生」、§三「F 事实层 = 飞书黑板」 vs §1.2/§八「没进控制台库 = 没发生」 | 以**控制台库**为唯一事实源；不使用黑板、不做投影（见 §7-B8） | v0.5 口径变更；黑板实际未使用 |
| 2 | 「一期」一词两义：§1.5 四屏 vs §11 M3 两屏 | 拆分为 MVP / 一期 / 二期，定义见 §2 | 里程碑是交付顺序，分期是对外口径 |
| 3 | §4.3/§十「不改 cc-connect 配置」 vs §3.4「要改它的触发源」 | R1 观测层**不改** cc-connect；R5 的 A2A 唤醒**必须改**其触发源。两条并行成立，各自限定适用范围 | 观测只读会话文件，唤醒要注入 turn |
| 4 | §十「控制台可随时停，停掉不影响任何任务执行」 vs M2.5 后 A2A 走控制台 | 该条**仅适用于 M2.5 之前**。M2.5 后停机不丢消息（排队补投），但 Agent 间通信在停机期间中断 | §3.4 离线排队设计 |
| 5 | §3.7 引用「按 2.3 升格」 | 应为「按 3.3 升格」 | 笔误 |
| 6 | 原型 `cap-8821 read · 7d` vs §5.2 TTL 最长 4 小时 | 以 §5.2 为准：凭证 TTL 默认 15 分钟、最长 4 小时；原型标注待修 | 凭证有效期是 R2 核心验收项 |
| 7 | 原型位置：原文提及 `prototype/console.html`，仓库无此文件 | 原型以 Ardot 文件 741613178974645 为准（链接见 02 文首与 `docs/README.md`） | 原型已迁至 Ardot |

## 7. 已裁决的开放问题（2026-10-29）

| # | 问题 | 裁决 | 备注 |
|---|------|------|------|
| B1 | 跨机通道 | 复用既有 frp 公网入口，不引入 Tailscale 等第三方组网 | 控制台仍只绑 127.0.0.1，由 frpc 转发 |
| B2 | 采集器跨机 | 每台机跑采集器（Node，launchd 常驻），增量读会话文件后推 `/api/ingest` | 采用 inode + offset 断点、ACK 后推进、持久化缓冲 |
| B3 | WorkBuddy 唤醒 | 暂缓，M2.5 不实现；上线后按序补投 | 不阻塞其他里程碑 |
| B4 | 授权对象 | SSH、密钥、云资源、数据库；读写均需授权 | 登录方式已确认为 SSH；服务器明细仍待补（§12-4） |
| B5 | 授权实现 | Teleport CE + tbot：15 分钟短时证书、自动续期、会话录制与审计；覆盖 SSH 与数据库 | 不自研证书签发；吊销以 TTL 自然过期为主；A 类只读 API 代理仍自建 |
| B6 | 审批主体 | 仅本人批准；未来成熟后再逐步授权给专用 Agent | 卡片回调需签名校验 + open_id 白名单 |
| B7 | frps 与域名 | 已有 frps、`example.com` 与 Docker 版 frpc；新增一个 http 代理指向 127.0.0.1:8787 即可 | frpc 在容器内，`localIP` 用 `host.docker.internal` |
| B8 | 黑板 | 停用，删除全部投影要求 | 飞书侧「看全表」由手机端控制台承接；周报改推卡片 |
